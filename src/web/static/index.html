A probe prices every route on three spread-out dates. It will not find you a trip; it says which airports are hopeless, so a sweep can leave them out — the verdicts land under Probe results. A sweep prices the whole window and its itineraries land under Search results.

All three run in the cloud, on the trip committed and pushed — your machine is one address and pelikan.cz answers about 120 searches from it before it stops answering at all. A run in progress can be stopped from the strip at the top; it keeps what it has found.

Discord

—

Where a sweep posts, and what it posts. In Discord: Edit Channel → Integrations → Webhooks → Copy Webhook URL.

This URL is a password in disguise — anyone holding it can post to the channel — so it is stored in .secrets/discord.json, outside everything git tracks. It is never sent back to this page; the field above shows it masked. Cloud sweeps do not read that file. They read the repository secret, which you set once with gh secret set DISCORD_WEBHOOK_URL. When that variable is present it wins, so a cloud run always posts where the secret says.

Your preferences

—

The two or three trips you are deciding between, ranked in the order you would take them. Each is pinned to the dates you picked and re-priced on them every four hours, plus a couple of days either side — so it can tell you that the same trip two days later is two thousand cheaper, and offer to move to it. The line is always the trip you chose, never the cheaper neighbour; a series that drifted would draw a fall you could not act on.

Lines share one set of axes on purpose: the question is which of these to book, and that is a comparison. A point drawn hollow came from a run the site refused part of — the gap is worth seeing, the price in it is not a price. Discord hears about one only when it falls by more than 1%, because this site moves fares by a few crowns at a time and those are not news.

Volatility probe

Three fixed routes sampled every two hours, to decide whether daily sweeping is often enough. Net move is first observation to last — the figure that says whether a fare is running away from you. Steps that moved counts any change at all, including the site rounding by a few crowns; the column beside it counts only moves worth noticing, and the gap between the two is why the steadiest route here used to report the highest volatility.

Scheduled sweeping

Runs in the cloud, on the trip committed to the branch, whether or not this page is open. It is also the only place a full-sized trip finishes: pelikan.cz answers about 120 searches from one address, and the cloud splits the plan so no runner is handed more than 100.

A fraction of the searches a broad sweep makes, so it can run several times a day against a site that answers about 120 per address. The point is not one more price: it is the same price on Monday, Tuesday and Wednesday, so a drop is visible as a drop. It does not replace the nightly sweep — that one goes on pricing the whole window, so a cheaper week outside your dates is still found.
