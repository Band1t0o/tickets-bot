Airports you'd rather fly from

Best first. A trip counts as belonging to a tier only when it both leaves from and returns to that tier — flying out of Prague and home into Frankfurt still strands you in Frankfurt. The best tier that has any trip at all wins, and the message says what preferring it cost against the outright cheapest.

Run

—

Explore first prices every route in this trip on three spread-out dates — a few minutes rather than an hour and a half. It will not find you a trip; it tells you which airports are hopeless, so the real sweep can leave them out. The verdicts land in Explore, with a button to drop an airport from the trip.

Local runs use your machine; cloud runs are free, since the repo is public. What limits depth now is pelikan.cz rather than minutes — it has throttled this client into mass timeouts before, and a sweep that half-fails is worth less than a shallow one that works. The estimate above is measured at the current pace, so it moves when the sweep settings do. A run in progress can be stopped from the strip at the top; it keeps everything it has already found.

Volatility probe

Three fixed routes sampled every two hours, to decide whether daily sweeping is often enough. Net move is first observation to last — the figure that says whether a fare is running away from you. Steps that moved counts any change at all, including the site rounding by a few crowns; the column beside it counts only moves worth noticing, and the gap between the two is why the steadiest route here used to report the highest volatility.

Where the prices come from

Sites move their URLs and rename their CSS classes, and either one stops the sweep without stopping the code. Both are strings, and both are here — edit the one that broke, press Test this source to run a single real search, and read what it parsed. Zero cards matched means the markup changed; a page that will not load at all means the URL did. Leave a field alone and it keeps the built-in value, so deleting data/sources.json always restores working defaults.

Where results get sent

—

The Discord webhook the picks above are posted to. In Discord: Edit Channel → Integrations → Webhooks → Copy Webhook URL.

This URL is a password in disguise — anyone holding it can post to the channel — so it is stored in .secrets/discord.json, outside everything git tracks. It is never sent back to this page; the field above shows it masked. Cloud sweeps do not read that file. They read the repository secret, which you set once with gh secret set DISCORD_WEBHOOK_URL. When that variable is present it wins, so a cloud run always posts where the secret says.
